# 测试与验收计划

## 1. 测试分层

### 单元测试

覆盖时间处理、电价匹配、SOC 计算、功率平衡、规则调度、经济性公式和数据校验。

### API 测试

覆盖创建站点、上传数据、读取电价、生成调度和错误响应。

### 集成测试

覆盖数据库、Provider、应用服务和 API 的组合。

### 前端测试

覆盖站点选择、请求状态、曲线渲染、空状态和错误状态。

### 端到端测试

覆盖“创建站点 → 上传数据 → 生成调度 → 查看曲线”。

## 2. 必测业务案例

1. 夜间谷段充电，SOC 不超过上限。
2. 峰段放电，SOC 不低于下限。
3. 光伏余电充电。
4. 无光伏和无负荷数据的异常处理。
5. PCS 功率小于需要功率时正确截断。
6. 禁止反送电时电网功率不为负。
7. 低于完整一天的数据不被静默补齐。
8. 峰谷边界时刻只命中一个档位。
9. round-trip efficiency 转换可复现。
10. 相同输入和版本得到相同输出。

## 3. API 验收

- OpenAPI 文档可访问。
- 所有接口返回统一错误结构。
- 时间和单位字段符合契约。
- 非法 site_id 返回 404。
- 非法时间序列返回 422 或约定的数据质量错误。
- 调度结果包含完整的时间点和约束说明。

## 4. 发布前检查

- 干净环境安装和启动成功。
- 单元测试全部通过。
- API 集成测试全部通过。
- 前端生产构建成功。
- Docker 启动说明与实际命令一致。
- 示例数据可以从头到尾运行。
- 所有已知限制写入 README 或决策记录。

## 5. 质量门槛

任何涉及收益、调度或容量建议的功能，都不能仅以“页面显示出来”为完成标准，必须同时验证：

- 输入数据口径
- 约束是否生效
- 输出单位
- 结果可复现性
- 假设和限制是否可见
