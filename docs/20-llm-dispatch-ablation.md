# 20 · LLM 调度消融的解释边界与后续协议

> 状态：已完成一次真实本地 LLM P0 试运行，并完成封存与离线诊断。本文件解释该结果能证明什么、不能证明什么，以及下一轮如何改变 LLM 的角色；不改写原始运行结果。

## 1. 已封存结果

真实运行使用 `qwen2.5:7b` / Ollama，窗口为 2019-04-01 至 2019-04-30（Asia/Shanghai），30 天每日一次调用。30/30 调用成功，0 次降级，0 次 SOC 违规。E_LLM 电费为 **206,479.28 元**，相对 E0 节省 **8,955.03 元**，但比 E2 多花 **9,557.02 元**，约高 **4.6%**（按 E2 电费计）。

对应原始报告、逐日结果、策略归档、诊断和哈希清单见 [`reports/generated/llm_live_p0_20261024/`](../reports/generated/llm_live_p0_20261024/)。原始数据与数值不在本文件重算或改写。

## 2. 该负结果站得住的范围

这是一条干净的消融结论：在公开光伏代理、仿真负荷、政策价格演示场景和本次冻结提示词下，当前 E_LLM 接口没有带来平均电费收益；它同时满足成功率、可复现性和安全约束记录要求。它不能被表述为“LLM 不适合调度”或“换一个模型就一定能改善”。

当前接口允许 LLM 只返回两个参数：`soc_min_safe` 与 `peak_discharge_offset`。充放电动作仍由既有 `actions_llm_guided`、`execute` 和硬安全边界执行，LLM 相当于在已经调好的 E2 规则上做有限微调。若该接口的期望增益接近 0 而输出存在方差，均值略输是合理的接口下界；这说明的是接口表达能力和评价窗口的结果，不是模型能力上限。

本轮输入也没有把价差、事件状态、检修、寒潮、限电或负电价等结构化信号作为独立决策特征提供给 LLM。因此不能用本轮结果判断 LLM 在事件场景或更丰富约束建模中的价值。

## 3. 后续角色设计

下一轮应先改变 LLM 的角色，再比较模型大小：

1. **LLM-as-formulator**：LLM 输出场景标签、约束、风险权重或目标函数参数，例如检修、寒潮、限电、负电价对应的 SOC 下限、放电窗口和备用要求；数值可行性与动作求解仍交给规则引擎或 LP。LLM 不直接生成 96 点计划。
2. **事件日接管**：普通日继续使用 E2；只有事件日或 E2 明确薄弱的场景才启用 LLM 生成的约束/场景臂。事件定义、发布时间和可用性必须在发报时刻冻结，不能使用事后信息。
3. **扩展评价**：除平均电费外，预先增加最差日、CVaR、尾部电费、SOC 违规、功率越限、人工干预次数和事件日收益，并继续报告按日配对 bootstrap 95% CI。任何新增指标都必须在实验前冻结口径。

## 4. 下一轮最小实验协议

在未用于本轮的独立窗口上，固定 E2、LLM-as-formulator 和事件日接管三臂；输入同时保留价格结构、预测价差、事件日历和约束状态。至少报告：总电费、日节省 p10/p50/p90、最差日/CVaR、SOC 与功率违规、人工干预次数、事件日子集收益，以及相对 E2 的配对 95% CI。平时走规则、事件日才调用 LLM 的选择规则必须在实验开始前写入 `run_meta.json`。

本轮真实 LLM 结果不得与下一轮调参结果合并成一个估计，也不得因新增指标而删除本轮均值电费结论。

## 5. 结论层级

- **可以宣称**：本窗口、当前两参数接口、当前数据口径下，E_LLM 安全运行但平均电费劣于 E2；该结果已封存且可复核。
- **不能宣称**：LLM 总体不适合调度、LLM 在事件日无价值、或换用更大模型即可逆转结果。
- **下一步目标**：验证 LLM 作为约束/场景建模者，或只在事件日提供高层策略，再由现有执行器保证可行性。
