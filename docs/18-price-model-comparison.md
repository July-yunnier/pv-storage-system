# 18 · 双电价模型对比与组合方案（July MQ-RNN × 林 LightGBM）

> 背景：2026-10-21 July 与林各自上传了一个电价预测模型，要求评估"哪个好、怎么组合"。
> 本文档是评估结论与落地决策，也是后续同协议对决实验的设计依据。

## 1. 结论先行

1. **两个模型都是真模型、都样本外有效，但测试协议不同，不能直接比谁 MAE 低。**
   林的 LightGBM 在 360 个竞争选定任务点上 skill +29.1%；July 的 MQ-RNN 在 3744 个
   连续窗口点上 skill +20.2%。测试集大小差 10 倍、预测时域不同（24h vs 96h）、
   训练信息量不同（逐日重训 vs 单次训练），绝对值不可互比。
2. **泄漏检查通过**：July 的模型按绝对时间切分，训练截止 2013-01-26、验证截止
   2013-07-07，全部测试点在其后（2013-07-11 ~ 2013-12-14），不存在用未来训过去。
   林的协议逐任务日滚动重训，同样只用 origin 之前的数据。两侧都干净。
3. **生产骨干维持林的 LightGBM 不变**——它已在主线、工程链完整（注册表、降级链、
   前端、测试），且峰值命中率 0.75 是储能套利最吃的指标。
4. **July 的 MQ-RNN 不当替代品，当补充**：它最大的长处是**区间校准好**
   （80% 区间实测覆盖 81.4%，几乎完美；林的 LightGBM 只有 68.6%，区间偏窄）。
   调度器做"今天该保守还是激进"的风险决策时，校准好的区间比更低的 MAE 更值钱。
5. **组合方向：树模型 + 神经网的双臂结构**，而不是 MQ-CNN + MQ-RNN——
   后者同属 arXiv:1711.11053 一个论文家族，构不成多样性。真正的多样性在
   LightGBM（梯度提升树，吃手工特征）与 MQ-RNN（序列神经网，自动学时序模式）之间。
6. **正式对决必须同协议重跑**（§5），在跑完之前任何"A 比 B 强"的说法都不成立。

## 2. 两个模型的身份卡

| | 林 · LightGBM 分位数 | July · MQ-RNN |
|---|---|---|
| 位置 | 主线 `backend/app/domain/forecast/price_model.py`（PR#5 已合并） | `product/` 旧树 `price_mqrnn.py`（feat/product-mvp-impl 分支） |
| 论文谱系 | 梯度提升树 + 分位数损失 | arXiv:1711.11053 MQ-RNN 的独立复现改（forking-sequences、共享解码器、截断 BPTT，论文级忠实） |
| 数据集 | GEFCom2014-P（真实市场 LMP） | 同 |
| 协议 | 15 个竞赛任务日 × 24h = 360 点，**逐日滚动重训**，日前 24h | 39 个连续 96h 窗口 = 3744 点，**单次训练**（20 轮，验证集选第 17 轮），96h 长时域 |
| MAE | 9.24（基准 naive_daily 13.03） | 8.74（基准 seasonal_day 10.95） |
| skill | +29.1% | +20.2% |
| 80% 区间覆盖率 | **68.6%（偏窄，低估尾部）** | **81.4%（≈名义 80%，校准优秀）** |
| 峰值命中率 | 0.75 | 未评（该指标在其协议下未定义） |
| 工程状态 | 注册表算法臂、降级链、前端、17 项测试，**已在生产链路** | 工件 + manifest + 3745 行逐点预测存档齐全，但单位/时区与线上不符，作者自标"未安装为生产模型"；代码在废弃 product/ 树 |
| 自检诚实度 | 明确记录"MQ-CNN 没赢，不修饰" | manifest 自标"calendar-only adaptation，非竞赛分数复现，未做中国站点验证" |

两个模型的测试期有 9 个任务日重叠（07-13~07-25、12-07、12-08），具备做
**逐点对决**的数据基础（见 §5）。

一个需要双方都正视的事实：July 的测试存档显示 2013-12-13/14 实际电价冲到
134.81/80.08，MQ-RNN 的 P50 只给到 43.5/38.8——**12 月尖峰被系统性低估**。
林的文档同样指出任务日集中在 6–7 月与 12 月的厚尾时段是区间偏窄的主因。
这不是谁的模型差，是电价这个对象的固有难点：极端价格由稀缺性与市场博弈驱动，
纯历史外推都抓不全。对储能套利的影响：错过最贵的放电窗口比买贵一点电损失大得多。

## 3. 为什么不能直接比 MAE

| 差异 | 影响 |
|---|---|
| 测试点数 360 vs 3744 | 林的任务日是竞赛方挑的"难题日"（6-7 月、12 月厚尾），July 的窗口含大量普通日；难题日 MAE 天然偏高 |
| 时域 24h vs 96h | 误差随提前量增长，96h 平均 MAE 与 24h MAE 不是一个量 |
| 逐日重训 vs 单训 | 林每个任务日都用到前一天的数据；July 的模型从没见过 2013-01-26 之后的任何数据，对 12 月测试点等于"用一年前的知识考年底的试" |
| 基准不同 | naive_daily 与 seasonal_day 口径相近但不保证逐点一致 |

结论：skill +29.1% vs +20.2% 的差距里，协议差异的贡献未知，不能归因于模型强弱。

## 4. 组合方案（落地决策）

### 4.1 生产链路（现在）

- 骨干不变：`price_lgbm_quantile`（林）为注册表默认算法臂，降级链、封存对账照旧。
- 区间策略：LightGBM 的 P10/P90 偏窄已知（docs/15 §4.3 第 3 条），在 conformal 校准
  落地前，调度器风险挡位继续按"区间偏窄"保守解释，不展示虚假的精确感。

### 4.2 MQ-RNN 的接入定位（下一步）

July 的模型要进系统，不是复制文件，而是**按注册表契约重做接入**：

1. 从 `product/` 旧树移植 `price_mqrnn.py` 到主线 `app/domain/forecast/`，
   实现 ForecastAlgorithm 契约（含 probe 探针字段）；
2. **用本站真实现货数据逐站重训**——GEFCom 工件单位是源市场 $/MWh、时区 UTC、
   小时级，与线上 CNY/kWh、Asia/Shanghai、15 分钟不匹配，不可直接上线
   （其 manifest 已自标此限制）；
3. 注册为第二算法臂 `price_mqrnn`，与 `price_lgbm_quantile` 并存，
   由封存对账积累本站实绩后再谈切换或融合；
4. 区间来源候选：MQ-RNN 的校准优势若在本站复现，可升级为主区间来源。

### 4.3 融合方向（同协议对决之后才有数据支撑）

- 点预测：两臂 P50 取中位数（对异常值稳健，通常优于单臂）；
- 区间：分位数平均或按历史 pinball 加权；
- 不做：MQ-CNN + MQ-RNN 互融（同族，多样性收益≈0）。

## 5. 正式对决实验设计（补进 docs/17 实验规划）

目标：在同一协议下回答"谁强、是否值得融合"。

- **协议**：采用林的 15 任务日滚动重训协议（更严、更贴近线上逐日发预测的真实场景）。
- **做法**：用 July 的 `train_price_mqrnn.py` 在每个任务日 origin 截断重训 MQ-RNN
  （或直接跑 forking-sequences 推理若支持滚动 origin），产出同样 360 点；
  与 LightGBM 逐点对齐比较 MAE / pinball / PICP80 / 峰值命中。
- **代价**：15 次 MQ-RNN 训练，CPU 单次约分钟级（模型仅 hidden=30），总成本可忽略。
- **判据**：不预设胜者；若两臂误差相关性低（<0.7），即使一方 skill 略低，
  融合臂仍有正收益，进 docs/17 的消融矩阵。

## 6. 附：AMPDNet（July 10-20 上传的光伏深度模型）现状

与电价模型分开记录，避免混淆——这是**光伏功率**模型，不是电价模型。

- **交付完成度高**：Solar1/2/6/7/8 × 15min/1h/4h 共 15 个权重全部完成 20 轮训练
  （按验证集 MAE 选轮，非第 2 轮草稿），TorchScript 图 + 元数据 + 校验值齐全；
  `verification.json` 显示 113,695 个测试窗口、794,530 个预测点全部数值验证通过，
  TorchScript 与 eager 输出逐点一致（max diff = 0.0）。这份交付的工程严谨度很高。
- **但它不是插上就能用的**：
  - 输入是 TSI/DNI/GHI/温度共 4 通道的**白昼压缩采样**（06:00–18:45 每 15 分钟，
    夜间被压缩掉），不是历史功率；我们的站点没有 TSI（总天空成像）数据源；
  - 源站是 30–130 MW 的地面大站，与我们 1000 kWp 屋顶场景量级差两个数量级，
    manifest 明确"未验证跨站泛化、不支持跨容量缩放"；
  - 只输出同日白昼、**拒绝跨夜**——它是日内滚动修正模型，不是日前预测模型；
  - 上游训练库 pinned checkout 无 LICENSE，再分发许可未确认。
- **系统内定位**：若接入，对应光伏链路的"15 分钟~4 小时短临滚动修正"档位
  （docs/12 路线图中预留给天空相机/云图算法的位置），需用本站数据重训后
  经注册表登记为 opt-in 实验臂，**不替代默认物理链**。接入代码
  （`ampdnet.py`，输入校验写得相当严格）可从 product/ 树移植，但优先级低于
  电价同协议对决与 docs/17 主实验。
