# 文档索引

## 1. 阅读顺序

建议第一次阅读按以下顺序进行：

1. 本文件和 `README.md`
2. `01-prd.md`：理解产品为什么做、为谁做、做到什么程度
3. `02-scope-roadmap.md`：理解首版边界和阶段目标
4. `04-domain-model.md`、`05-api-contract.md`：理解数据和接口契约
5. `06-technical-architecture.md`、`07-optimization-model.md`：理解实现方式
6. `08-ui-spec.md`、`09-test-acceptance.md`：理解交互和验收
7. `10-open-decisions.md`、`11-development-plan.md`：查看待定项和执行顺序

## 2. 文档责任

| 文档 | 主要读者 | 作用 | 状态 |
|---|---|---|---|
| PRD | 产品、研发、业务方 | 定义目标、范围和需求 | 初稿 |
| 范围与路线图 | 项目负责人 | 定义阶段和优先级 | 初稿 |
| 用户故事 | 产品、测试、前后端 | 定义用户行为和验收 | 初稿 |
| 领域模型 | 后端、算法、前端 | 定义领域对象和字段 | 初稿 |
| API 契约 | 前后端、集成方 | 定义输入输出 | 初稿 |
| 技术架构 | 研发、部署人员 | 定义工程结构和运行方式 | 初稿 |
| 优化模型 | 算法、后端、产品 | 定义调度和收益计算口径 | 初稿 |
| UI 规范 | 前端、产品、设计 | 定义页面和图表行为 | 初稿 |
| 测试计划 | 测试、研发、负责人 | 定义质量门槛 | 初稿 |
| 决策记录 | 全体成员 | 管理假设和未决问题 | 初稿 |
| 开发计划 | 项目负责人、研发 | 定义任务、依赖和交付物 | 初稿 |

## 3. 变更规则

- 影响数据字段、计算口径或 API 的变更，必须同步更新领域模型、API 契约和测试计划。
- 影响产品范围的变更，必须同步更新 PRD、范围路线图和开发计划。
- 未关闭的待确认项不得被实现为不可逆的业务规则。
- 每个重要决策都应在 `10-open-decisions.md` 追加记录，而不是只留在聊天记录中。

- [MQ-RNN 电价模型与训练验证](15-price-mqrnn.md)：论文结构、两省 TOU 配置、现货预测与精度口径。
